# Фронтенд карьерной платформы ФСП

React + Vite. Профили, анкеты, потребности и приглашения хранятся на бэкенде. Роль берётся из аккаунта после входа.

## Запуск в PowerShell

Бэкенд должен отвечать на `http://localhost:8000`. Оставьте его PowerShell с `docker compose up --build` открытым.
Во втором PowerShell:

```powershell
cd C:\Users\HUAWEI\IdeaProjects\LLH_BY_KARMA\frontend
npm.cmd ci
npm.cmd run dev
```

Откройте адрес, который напечатал Vite; обычно это `http://localhost:5173`.
Команда `npm.cmd` работает без изменения политики выполнения PowerShell.

Если бэкенд на другом компьютере, скопируйте `.env.example` в `.env.local`, задайте `BACKEND_URL` и перезапустите Vite.

## Что подключено

Вход, выход, регистрация, подтверждение почты и вход через FSP ID; загрузка и сохранение профиля, распознавание PDF-резюме с проверкой перед сохранением. Анкета получает справочники с сервера и передаёт навыки и опыт, которые требует текущий бэкенд.

Тест использует серверные задания, таймер и оценку. Незаконченная попытка восстанавливается через API; черновик ответов остаётся в sessionStorage текущей вкладки. Без связи после истечения времени интерфейс предлагает повторить отправку. Сервер решает, можно ли ещё принять ответы.

Работодатель сохраняет компанию и потребности, получает подборку с объяснениями и отправляет приглашение с зарплатной вилкой. Кандидат принимает или отклоняет предложение; интерфейс работодателя показывает контакты только из ответа сервера. После ответа кандидата обновите подборку и снова откройте карточку.

Кандидату доступны согласия, настройки видимости, необязательная привязка ФСП, PDF-профиль, выгрузка данных, история доступа к контактам и удаление аккаунта с паролем и подтверждением. Журнал доступа имеет свободную схему в предоставленном OpenAPI; его реальные поля нужно проверить на вашем сервере.

ФСП влияет на подбор внутри категории, а грейд подтверждается тестом. Тест относится к специализации и грейду, не к отдельной вакансии. Интерфейс отображает решение сервера и не понижает грейд самостоятельно.

## Проверка на вашем бэкенде

Демо-аккаунты: `candidate@demo.ru`, `newbie@demo.ru`, `employer@demo.ru`, `hr1@demo.ru`. Пароль у всех `demo12345`. Кнопки быстрого входа доступны только в режиме разработки.

1. Работодатель: сохраните компанию, выберите потребность, откройте подборку и карточку кандидата. До принятия приглашения контакты должны быть скрыты.
2. Отправьте приглашение с зарплатной вилкой. В аккаунте кандидата откройте предложение и примите его; затем вернитесь к работодателю и обновите карточку.
3. Новичок: заполните профиль и анкету, пройдите тест и сохраните согласия. Проверьте категорию и появление в подборе.
4. Проверьте PDF, ФСП и историю доступа к контактам. После принятия приглашения закройте доступ к контактам для компании и проверьте карточку работодателя после обновления.

## Обновление по ответам организаторов

На входе и регистрации появилась кнопка FSP ID, если сервер включает этот способ входа. Имитация входа обозначена явно. Встроенные демо-аккаунты FSP ID используют пароль `fsp12345`: `maria.fsp@demo.ru`, `olga.fsp@demo.ru`, `ivan.fsp@demo.ru`, `candidate@demo.ru`. Это другой пароль, чем для обычного входа платформы. После возврата новый кандидат попадает на анкету; согласия сохраняются отдельно.

Обязательные поля анкеты: IT-направление и заявленный грейд. Сфера бизнеса необязательна. Кандидатов без теста может показывать сервер; карточки используют `grade_status_label`, а переключатель «Только подтверждённые» передаёт `only_verified`.

Приглашение содержит `salary_type`: gross до вычета НДФЛ или net на руки. Кандидат может закрыть и снова открыть контакты для компании у принятого приглашения. Профиль ФСП показывает разряд и ссылки на протоколы, если их вернул сервер.

В разделе ATS можно настроить HTTPS-вебхук, получить секрет, проверить доставку, сменить секрет и отключить интеграцию. Секрет показывается только из ответа настройки и исчезает после закрытия экрана; фронтенд его не сохраняет.

На текущем запущенном бэкенде пользователя нет маршрутов с `needs` в OpenAPI. Новый API-клиент оставляет `/api/employer/needs` без изменений, поэтому это обновление не исправляет 404 потребностей. Нужно согласовать с бэкендером версию реально запущенного сервера. Новые функции FSP ID, отзыва контактов и ATS также требуют обновлённого сервера.

## Общая Docker-сборка

В командном репозитории рядом с `frontend/` нужны `backend/` и существующий `docker-compose.yml` с сервисом `backend` на порту 8000. Добавочный файл из архива подключает фронтенд:

```powershell
docker compose -f docker-compose.yml -f docker-compose.frontend.yml up --build
```

Перед запуском остановите Vite, чтобы освободить порт 5173. nginx пересылает `/api/` в контейнер `backend:8000`.
Для обычного `docker compose up --build` перенесите блок `frontend` из добавочного файла в основной compose. Сам основной файл бэкенда в присланном архиве отсутствует, поэтому общая Docker-сборка здесь не проверена.

## Проверки этой версии

`npm ci`, сборка и ESLint. Отдельные проверки компонентов с подменой API проверяют анкету, таймер, восстановление ответов, переход статуса приглашения, скрытие и раскрытие контактов, зарплатную вилку, сохранение компании и потребностей, согласия и ФСП. Они не заменяют прогон на вашем бэкенде.

Monaco загружает редактор через CDN; для первого открытия задачи с кодом нужен интернет.
