ФСП Таланты — LLH_BY_KARMA

Платформа подбора IT-кандидатов: профиль и резюме, подтверждение грейда тестом, поиск работодателя, вакансии, отклики, приглашения и короткие задания. Итоговая сборка объединяет интерфейс и основной API; ML-модули работают внутри бэкенда.

Это текущая демонстрационная версия команды. Автоматические проверки описаны в отчёте. Независимое тестирование участником команды запланировано на 11 октября 2026 года; его результаты ещё не включены. Готовность к промышленному запуску не заявляется.

Запуск с нуля

Нужны Git и запущенный Docker Desktop с Docker Compose. В PowerShell:

git clone https://github.com/NedYouNet/LLH_BY_KARMA.git

cd LLH_BY_KARMA

git switch main

docker compose up -d --build

docker compose exec backend python -m scripts.seed

Первый запуск скачивает образы и зависимости. Миграции выполняются при старте бэкенда. Seed создаёт демо-данные; без --reset он не пересоздаёт уже заполненную демо-базу. При ошибке запуска: docker compose ps и docker compose logs backend --tail 100.

Почта в серверном демо

Сайт: https://lct.demo.bloomee.ru. Письма подтверждения: https://mail.lct.demo.bloomee.ru.
На странице подтверждения почты есть ссылка на ящик и инструкция. Локально эта ссылка ведёт на порт 8025 своего компьютера.

Mailpit — общий демонстрационный ящик, а не доставка на реальные почтовые адреса. Не используйте здесь реальные персональные данные. После демонстрации закройте общий доступ.

HTTPS-адрес Mailpit служит только для чтения писем. Бэкенд должен отправлять их по SMTP в тот же экземпляр Mailpit: при общей сети Docker это SMTP_HOST=mailpit, SMTP_PORT=1025. Не указывайте HTTPS-адрес в SMTP_HOST. На сервере задайте BACKEND_PUBLIC_URL=https://lct.demo.bloomee.ru и FRONTEND_URL=https://lct.demo.bloomee.ru в окружении сервиса backend. Корневой .env сам по себе не переопределяет фиксированные значения в Compose: перенесите настройки в секцию environment либо используйте серверный Compose override.

После обновления main пересоберите интерфейс: docker compose up -d --no-deps --build frontend. При изменении окружения бэкенда пересоздайте его: docker compose up -d --no-deps backend. Базу и seed сбрасывать не нужно. Для проверки зарегистрируйте тестовый адрес, найдите письмо в Mailpit и подтвердите его через сайт.

Работа тестирования не требует ключа GigaChat. Для нейросетевого разбора PDF можно скопировать .env.example в .env, указать GIGA_TOKEN и пересоздать контейнер: docker compose up -d --build backend. Ключ остаётся на сервере. Без ключа используется встроенный парсер. Вход ФСП по умолчанию работает в демонстрационном режиме mock, а ATS имеет локальный тестовый приёмник.

Что можно проверить в интерфейсе

Кандидат заполняет профиль, загружает PDF, выбирает направление и грейд, проходит тест, получает приглашения, отвечает на короткие задания и управляет доступом к контактам. Работодатель задаёт потребность, ищет кандидатов, смотрит вклад факторов в оценку соответствия, создаёт вакансии и задания, оценивает ответы и проверяет ATS. Светлая и тёмная темы переключаются в шапке.

Тест содержит три задачи на Python выбранного грейда: лёгкую, среднюю и сложную. Поддерживаются Backend, Frontend, Data Science, QA и DevOps; грейды Intern, Junior, Middle, Senior. Банк содержит 60 шаблонов. Сюжетные тексты подготовлены заранее, данные генерируются функциями банка при старте попытки.
Часть шаблонов пока имеет фиксированные данные — полная уникальность всех вариантов не заявляется.

|Задача |Баллы за долю пройденных тестов|Бонус за все тесты|Максимум|
|-------|------------------------------:|-----------------:|-------:|
|Лёгкая |15 × доля                      |5                 |20      |
|Средняя|20 × доля                      |10                |30      |
|Сложная|35 × доля                      |15                |50      |

Суммарный максимум — 100. По каждой задаче доступны 10 предварительных проверок. Они не сдают попытку и не меняют грейд. Итог определяется кодом, отправленным при окончательной сдаче. Старые сохранённые попытки оцениваются по своей сохранённой структуре.

Остановить и включить снова

Из корня проекта: docker compose stop — остановить с сохранением базы; docker compose start — снова запустить. После изменения исходников используйте docker compose up -d --build. Команда docker compose down удаляет контейнеры, но сохраняет том базы. down -v удаляет также базу: для обычной остановки она не нужна.

Разработка фронтенда

Чтобы изменения React появлялись сразу, остановите контейнер фронтенда: docker compose stop frontend. Затем в frontend/: npm ci, npm run dev. Бэкенд остаётся в Docker. Для другого компьютера задайте BACKEND_URL в frontend/.env.local. Подробные команды — в инструкции.
