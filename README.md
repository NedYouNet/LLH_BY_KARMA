# 🧠 Техническая документация ML-микросервиса (FastAPI + GigaChat)

Эта документация предназначена для всех участников команды (Фронтенд, Бэкенд, Системный аналитик), чтобы вы могли быстро понять, как работает ML-ядро, как к нему обращаться и как развивать проект.

---

## 🏗 1. Архитектура и логика работы

Данный микросервис написан на Python (FastAPI) и выполняет роль интеллектуального шлюза. Он не работает с базой данных напрямую — его задача принимать сырые данные (текст, код), прогонять их через LLM или математические алгоритмы и отдавать строгий JSON.

**Используемые модели (GigaChat API):**

* `GigaChat` (базовая) — для быстрого и жесткого парсинга фактов из резюме.
* `GigaChat-Pro` — для креативной генерации легенд алгоритмических задач (семантическая маскировка).

---

## 📂 2. Структура проекта (Навигация по файлам)

Каждый файл имеет строгую зону ответственности. Если вам нужно что-то поменять, ищите это здесь:

* **`main.py`** — Точка входа. Здесь инициализируется сервер FastAPI и настроены CORS-политики (чтобы React мог делать запросы).
* **`config.py`** — Хранилище секретов. **(В репозиторий не загружается!)**. Здесь лежит `GIGA_TOKEN`. Каждый участник должен создать этот файл у себя локально.
* **`routers.py`** — Эндпоинты для обработки резюме. Взаимодействует с базовой моделью GigaChat для NLP-анализа.
* **`router_tasks.py`** — Эндпоинты для генерации уникальных соревновательных задач.
* **`prompts.py`** — Промпт-инжиниринг. Здесь лежат системные инструкции для нейросетей. Если модель отвечает «криво», править нужно этот файл.
* **`invariants.py`** — **Математическое ядро**. Словарь с жестко заданными параметрами задач и скрытыми Unit-тестами (`hidden_tests`), которые будут использоваться для проверки кода кандидатов на анти-чит.

## 🔌 3. API Контракты (Для Фронтенда)

Сервер работает на `http://localhost:8000`. Взаимодействие происходит исключительно через JSON.

### Эндпоинт 1: Парсинг резюме кандидата

* **Маршрут:** `POST /api/cv/parse`
* **Зачем нужен:** Превращает стену текста от пользователя в структурированный профиль.
* **Тело запроса (Request):**
```json
{
  "resume_text": "Строка с полным текстом резюме, скопированная кандидатом"
}

```


* **Успешный ответ (Response 200 OK):**
Обратите внимание, `extracted_data` возвращается как JSON-строка, на фронте нужно сделать `JSON.parse()`.
```json
{
  "status": "success",
  "extracted_data": "{\"full_name\": \"Иван Иванов\", \"grade\": \"Middle\", \"tech_stack\": [\"Python\", \"React\"], \"experience_years\": 2}"
}

```



### Эндпоинт 2: Генерация уникальной задачи (Анти-чит)

* **Маршрут:** `GET /api/tasks/generate`
* **Зачем нужен:** Берет шаблон задачи и придумывает для нее уникальную текстовую легенду, чтобы кандидаты не могли списать друг у друга.
* **Параметры URL (Query):**
* `task_id` (обязательно) — строковый ID математического шаблона (например, `sliding_window_1`).
* `theme` (необязательно) — тематика легенды (по умолчанию: `IT-инфраструктура`).


* **Успешный ответ (Response 200 OK):**
```json
{
  "task_id": "sliding_window_1",
  "difficulty": "Middle",
  "title": "Оптимизация пинга на серверах",
  "description": "Сгенерированная история про сервера...",
  "input_format": "Массив задержек ping, окно K",
  "output_format": "Максимальная задержка"
}

```

## 🛠 4. Инструкция для Системного Аналитика / ML (Как добавлять задачи)

Вся логика «честности» хакатона строится вокруг паттерна **Семантической маскировки**.
Чтобы добавить новую задачу в турнир, вам **не нужно** писать логику генерации. Достаточно добавить новый блок в файл `invariants.py`.

**Пример добавления новой задачи:**

1. Откройте `invariants.py`.
2. Добавьте новый ключ (например, `binary_search_1`).
3. Пропишите математическую суть и, самое главное, `hidden_tests`.

```python
"binary_search_1": {
    "difficulty": "Junior",
    "math_core": "Найти индекс элемента в отсортированном массиве за O(log n).",
    "inputs": "Отсортированный массив nums, целевое число target",
    "outputs": "Индекс (int) или -1",
    "hidden_tests": [
        {"input": ([-1,0,3,5,9,12], 9), "expected": 4},
        {"input": ([-1,0,3,5,9,12], 2), "expected": -1}
    ]
}

```

После этого фронтенд уже может вызывать `/api/tasks/generate?task_id=binary_search_1`, и система сама придумает легенду для бинарного поиска.

## 🚀 5. Как запустить проект локально (Инструкция для всей команды)

Каждый участник команды должен уметь запустить этот сервис на своем компьютере для интеграционного тестирования.

**Шаг 1. Скачать код**

```bash
git clone <ссылка_на_ваш_репозиторий>
cd <название_папки>

```

**Шаг 2. Настроить окружение**
Откройте терминал в папке проекта и установите библиотеки:

```bash
pip install fastapi uvicorn gigachat pydantic python-dotenv

```

**Шаг 3. Создать конфиг с ключом**
В корневой папке (там же, где `main.py`) создайте файл `config.py`. Вставьте в него ключ GigaChat (попросите его у ML-инженера):

```python
GIGA_TOKEN = "ВАШ_ДЛИННЫЙ_ТОКЕН_ЗДЕСЬ"

```

**Шаг 4. Запуск сервера**
В терминале выполните команду:

```bash
uvicorn main:app --reload

```

Если всё прошло успешно, вы увидите надпись `Application startup complete`.

**Шаг 5. Проверка работоспособности (Swagger)**
Откройте браузер по ссылке:
👉 **[http://localhost:8000/docs](http://localhost:8000/docs)**
Здесь вы увидите интерфейс Swagger, через который можно отправить тестовое резюме или сгенерировать задачу без использования Postman или написания кода на фронтенде.
