# Руководство по интеграции ML-микросервиса (FSP Hackathon)

Данный документ описывает, как внешним модулям (Frontend / Main Backend) взаимодействовать с ML-ядром платформы.

Микросервис представляет собой независимый REST API на базе FastAPI, работающий по умолчанию на порту `8000`. Взаимодействие происходит исключительно через JSON.

## 1. Базовая настройка и запуск (Для DevOps / Backend)

Перед интеграцией убедитесь, что микросервис запущен.

**Ключи доступа (Важно!):**
Микросервис требует наличия ключа авторизации GigaChat. В корне проекта должен быть файл `config.py` (или `.env`), содержащий:

```python
GIGA_TOKEN = "ВАШ_ТОКЕН_АВТОРИЗАЦИИ_GIGACHAT"

```

**Сетевые настройки:**

* По умолчанию сервис слушает `http://localhost:8000` (или IP контейнера).
* CORS уже настроен в `main.py` (разрешены все origin `*`), поэтому Frontend может делать запросы напрямую из браузера (fetch / axios) без блокировок.

## 2. Спецификация API (Для Frontend / Backend)

### 2.1. Парсинг резюме кандидата

**Эндпоинт:** `POST /api/cv/parse`
**Назначение:** Принимает сырой текст из резюме (или PDF-выжимку) и возвращает структурированный профиль с определенным грейдом.

**Запрос (Request Body):**

```json
{
  "cv_text": "Опыт работы 3 года, пишу на Python, знаю FastAPI и Docker. Участвовал в хакатонах."
}

```

**Ответ (Response 200 OK):**

```json
{
  "full_name": "Не указано",
  "grade": "Middle",
  "skills": ["Python", "FastAPI", "Docker"],
  "experience_years": 3
}

```

---

### 2.2. Генерация турнирного сета задач

**Эндпоинт:** `GET /api/tasks/generate-tournament`
**Назначение:** Формирует 3 уникальные задачи (Junior, Middle, Senior) в единой стилистике для защиты от списывания.

**Query-параметры:**

* `theme` (строка, по умолчанию "IT-инфраструктура") — сеттинг для задач (например: "Киберпанк", "Медицина", "Финтех").

**Пример запроса:**
`GET /api/tasks/generate-tournament?theme=Кибербезопасность`

**Ответ (Response 200 OK):**

```json
{
  "theme": "Кибербезопасность",
  "tasks": [
    {
      "task_id": "sequence_lookup_1",
      "difficulty": "Junior",
      "title": "Поиск зараженного лога",
      "description": "Текст легенды от нейросети...",
      "input_format": "Массив чисел и число",
      "output_format": "Индекс массива",
      "public_tests": [
        {
          "input": [[10, 20, 30], 20],
          "expected": 1
        }
      ]
    }
    // ... здесь же еще 2 задачи (Middle, Senior)
  ]
}

```

*Внимание фронтендерам: Поле `public_tests` нужно рендерить в UI кандидата как "Примеры (Sample Tests)".*

### 2.3. Автогрейдер (Проверка кода)

**Эндпоинт:** `POST /api/grader/submit`
**Назначение:** Безопасное выполнение Python-кода кандидата, проверка скрытыми тестами и статический анализ сложности (AST).

**Запрос (Request Body):**

```json
{
  "task_id": "continuous_stream_1",
  "candidate_code": "def solve(arr, k):\n    return sum(arr[:k])\n# ... остальной код"
}

```

**Ответ (Response 200 OK):**

```json
{
  "tests_passed": 2,
  "total_tests": 3,
  "ast_complexity": "O(n^2) или хуже",
  "final_score": 56.6,
  "details": [
    {
      "test_number": 1,
      "success": true,
      "error": ""
    },
    {
      "test_number": 2,
      "success": false,
      "error": "Time Limit Exceeded (Tle)"
    }
  ]
}

```

*Логика фронтенда: Если `final_score > 0`, можно показывать красивую анимацию начисления баллов.*

---

### 2.4. Умный матчинг (Кандидат <-> Вакансия)

**Эндпоинт:** `POST /api/match`
**Назначение:** Оценка совместимости кандидата и вакансии для кабинета работодателя (закрытие требования "Объяснимый подбор").

**Запрос (Request Body):**

```json
{
  "candidate_profile": "Python Middle, FastAPI, PostgreSQL",
  "vacancy_text": "Ищем Senior Python разработчика с опытом Kubernetes и Docker."
}

```

**Ответ (Response 200 OK):**

```json
{
  "match_percentage": 40,
  "explanation": "Кандидат имеет хороший фундамент в Python, однако не дотягивает по грейду (Middle вместо Senior) и не имеет заявленного опыта работы с DevOps инструментами (K8s, Docker).",
  "pros": ["Python", "FastAPI"],
  "cons": ["Нет Kubernetes", "Нет Docker", "Грейд ниже ожидаемого"]
}

```

## 3. Обработка ошибок (Error Handling)

Фронтенду необходимо корректно обрабатывать следующие HTTP-статусы, которые может вернуть наше ядро:

* **HTTP 404:** Задача не найдена (передан неверный `task_id` в грейдер).
* **HTTP 500:** Внутренняя ошибка сервера (чаще всего — не настроен `GIGA_TOKEN` в конфигурации).
* **HTTP 502 (Bad Gateway):** LLM (GigaChat) вернула мусорный ответ или невалидный JSON. Фронтенду следует показать тост: *"Ошибка генерации, попробуйте еще раз"* (при повторном запросе нейросеть сгенерирует новый, корректный ответ).
* **HTTP 422 (Unprocessable Entity):** Ошибка валидации Pydantic (фронтенд прислал данные в неверном формате, например, пропустил обязательное поле).
