# Запуск, обновление и остановка

## Чистая установка

Включите Docker Desktop. Скачайте ветку main, откройте PowerShell в папке с `docker-compose.yml`. Выполните `docker compose up -d --build`, затем `docker compose exec backend python -m scripts.seed`. Откройте http://localhost:5173. Миграции применяются автоматически. Для тестовой почты откройте http://localhost:8025.

## Если уже работали из другой папки

Сначала в старой папке выполните `docker compose stop`. Не запускайте одновременно старую и новую сборку на портах 8000/5173. Для самостоятельной чистой проверки в новой папке можно задать отдельное имя: `docker compose -p llh_main up -d --build`; все последующие команды также выполняйте с `-p llh_main`. Это создаст отдельный том и не перенесёт старую базу. Чтобы сохранить старую базу, оставайтесь с прежним именем Compose-проекта и сначала сделайте резервную копию данных.

Не копируйте `.env` и локальную базу в публичный Git. Старый `docker-compose.integration.yml` для этой сборки не нужен: текущие настройки ML уже находятся в основном compose. `backend/.env` для локального Python и корневой `.env` для Compose имеют разные области применения.

## Обновление после публикации

Сохраните свои изменения коммитом в рабочей ветке. Для отдельной чистой копии main: `git pull --ff-only`, затем `docker compose up -d --build`. Проверяйте `docker compose ps`, `/api/health` и `docker compose logs backend --tail 100`. Не считайте один только номер версии доказательством нового кода: смотрите поле build и исходный коммит.

Seed без reset предназначен для первой инициализации. `docker compose exec backend python -m scripts.seed --reset` удаляет тестовые аккаунты, вакансии, ответы и попытки, после чего создаёт демо заново. Используйте только если эти записи не нужны. После reset выйдите и войдите заново. `docker compose down -v` также уничтожает том базы и не нужен для обычного обновления.

## Разработка интерфейса

Из корня: `docker compose stop frontend`. Затем `cd frontend`, `npm ci`, `npm run dev`. Vite пересылает `/api` на localhost:8000. Если бэкенд на другом компьютере, задайте `BACKEND_URL=http://<IP>:8000` в `frontend/.env.local` и настройте доступ к API; текущий compose привязан к localhost. Сборка: `npm run build`. Проверка кода: `npm run lint`.

## Остановка

`Ctrl+C` останавливает foreground-процесс, например `npm run dev`. Docker, запущенный с `-d`, работает в фоне: остановите его командой `docker compose stop`. Для продолжения — `docker compose start`. После изменения исходников — `docker compose up -d --build`.

## Для сервера

Этот compose — локальная dev-сборка. Перед внешним развёртыванием нужны HTTPS, prod-настройки и собственные секреты, подтверждённая интеграция ФСП/ATS, изолированная среда исполнения кода, резервное копирование и проверка PostgreSQL/нагрузки. Здесь эти этапы не объявлены выполненными.
