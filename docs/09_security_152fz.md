# Обработка данных и ограничения безопасности

Бэкенд проверяет JWT и роли, маскирует контакты кандидата до разрешения работодателю, хранит согласия и поддерживает отзыв доступа. Поля персональных данных шифруются через AES-GCM; dev-ключ предназначен для локального стенда, а для prod нужны собственные ключи и процесс их хранения/ротации.

Перед отправкой текста резюме в GigaChat удаляются распознанные email, телефоны и Telegram. Регулярные выражения уменьшают раскрытие контактов, но не гарантируют удаление всех персональных данных из произвольного текста. Ключ GigaChat не отправляется в браузер и не хранится в репозитории.

Скрытые тесты остаются на сервере. Проверка кода использует AST-ограничения, таймаут и ограничения ресурсов. Исполнение произвольного Python в subprocess не является достаточной промышленной изоляцией. Перед публичным приёмом пользовательского кода нужна отдельная безопасная среда исполнения.

Наличие этих механизмов не является юридическим заключением о соответствии 152-ФЗ. Для реального запуска отдельно определяются оператор, основания обработки, сроки хранения, политика, доступы и договоры с внешними сервисами. Настройки TLS внешнего ML-клиента также требуют проверки перед prod.
