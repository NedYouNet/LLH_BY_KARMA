# 9. Безопасность и защита персональных данных (152-ФЗ)

## Права субъекта ПДн

| Требование | Как сделано |
|---|---|
| Согласие на обработку | Отдельная галочка при регистрации или в профиле; хранится с датой |
| Согласие на публикацию профиля работодателям | Отдельное согласие. Без него кандидат не виден в поиске |
| Минимум данных работодателю | До приглашения — «Иван П.», без контактов. Приватность настраивается: показывать ли полное имя, город, «о себе», достижения ФСП |
| Раскрытие только с основанием | Контакты — только после принятия приглашения или собственного отклика кандидата. Проверка на сервере |
| Отзыв доступа | Кандидат может закрыть контакты от компании после принятия |
| Прозрачность | Журнал «кто и когда видел мои контакты», включая передачу в ATS работодателя |
| Доступ к своим данным | Выгрузка всех своих данных в JSON |
| Удаление | Удаление аккаунта с подтверждением паролем |
| Трансграничная передача | Внешняя LLM только российская (GigaChat). Перед отправкой из текста резюме вырезаются почта, телефон и Telegram (`ml_client._mask_contacts`); контакты бэкенд извлекает сам. Без ключа GigaChat разбор идёт встроенным парсером внутри стенда |

## Угрозы и защита

| Угроза | Защита | Где в коде |
|---|---|---|
| Утечка дампа или бэкапа БД | ПДн (ФИО, телефон, Telegram, почта для связи, текст резюме, контакты HR, ответ кандидата, секрет ATS) хранятся зашифрованными **AES-256-GCM**. Ключ — только в переменной окружения; поддерживается ротация ключей | `core/crypto.py`, `scripts/encryption.py` |
| Утечка паролей | scrypt с солью; политика стойкости (8+ символов, буквы и цифры, запрет словарных) | `core/security.py` |
| Перебор паролей | 20 попыток входа в минуту с IP; блокировка email на 15 минут после 5 неудач (429) | `core/rate_limit.py`, `services/auth_service.py` |
| Перебор email | Одинаковый ответ и одинаковое время ответа для «нет пользователя» и «неверный пароль» | `services/auth_service.py` |
| Кража токена | Access живёт 15 минут; refresh одноразовый с ротацией; повторное использование старого refresh отзывает всю сессию; настоящий выход из системы | `models/security.py`, `services/auth_service.py` |
| Доступ к чужим данным | Роль и пользователь — только из токена; чужой объект = 404; контакты — по основанию | `core/deps.py`, `services/presenters.py` |
| Подмена входа через FSP ID | PKCE S256, подписанный `state` со сроком, `nonce`, точный `redirect_uri`, проверка подписи и полей `id_token` | `services/fsp_id_client.py` |
| SSRF через адрес ATS | В продакшене только https и запрет внутренних адресов | `services/ats_service.py` |
| Подделка событий для ATS | Подпись HMAC-SHA256 каждого события, идентификатор события для идемпотентности | `services/ats_service.py` |
| Вредоносный код в тесте | Статический анализ AST + отдельный процесс с лимитами времени и памяти; правильные ответы не уходят на фронт | `services/code_runner.py`, `services/testing_engine.py` |
| Атаки через браузер | Заголовки `nosniff`, `X-Frame-Options: DENY`, CSP, `no-store`; HSTS в продакшене | `app/main.py` |
| Небезопасный запуск | При `ENVIRONMENT=prod` сервер не стартует с дефолтным JWT-секретом, без ключа шифрования, с `CORS=*` или с незаданным FSP ID в режиме `oidc` | `core/config.py` |
| Расследование инцидентов | Журнал `auth_events`: входы, неудачи, блокировки, кражи токенов, входы через FSP ID; email хранится как HMAC | `models/security.py` |

```bash
python -m scripts.encryption gen-key   # новый ключ для DATA_ENCRYPTION_KEYS
python -m scripts.encryption check     # убедиться, что в БД нет открытых ПДн
python -m scripts.encryption rotate    # перешифровать всё новым ключом
```

## Несовершеннолетние (развитие)

По ответам организаторов поддержка 16–17 лет на MVP не обязательна. План развития: дата рождения в профиле;
для 15–17 лет — согласие законного представителя на обработку ПДн, отдельная пометка для работодателя
(трудоустройство только на лёгкий труд) и запрет приглашений на вакансии, не подходящие несовершеннолетним.
