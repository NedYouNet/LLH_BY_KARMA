# Фронтенд

Код лежит в `frontend/`. В разработке Vite пересылает `/api` на бэкенд; в Docker эту задачу выполняет nginx. Компоненты не сохраняют профиль, потребности и приглашения в localStorage. API-клиент хранит там сессию; черновик незаконченного теста хранится в sessionStorage вкладки.

## Экраны

| Экран | Компонент | Основные действия |
|---|---|---|
| Вход и регистрация | LoginForm, RegistrationForm, EmailVerification, FspIdLogin | Вход по почте, подтверждение почты, вход через FSP ID |
| Категория | CandidateOverview | Категория, статус грейда и шаги заполнения аккаунта |
| Профиль | CandidateProfile | Сохранение изменённых полей, распознавание PDF без автоматического сохранения |
| Анкета и тест | CandidateQuestionnaire, CandidateTest | IT-направление и грейд, необязательная сфера бизнеса, серверные задания и оценка, восстановление попытки |
| Приглашения | CandidateInvitations | Принять, отклонить, отозвать; gross/net; закрыть и открыть контакты после принятия |
| Согласия и ФСП | CandidateSettings | Согласия, приватность, привязка ФСП, разряд и протоколы, PDF и выгрузка данных, история доступа |
| Компания | EmployerProfile | Профиль компании и контакты HR |
| Потребности и подбор | EmployerNeeds, EmployerCandidates, InvitationModal | Потребности, серверная оценка соответствия, фильтр подтверждённых, приглашения |
| ATS | EmployerIntegrations | Настройка вебхука, одноразовый показ секрета, тестовая доставка и отключение |

## Решения организаторов

Роль задаёт аккаунт. Тест относится к IT-направлению и грейду, а ФСП влияет на подбор внутри категории. Заполненную анкету без теста сервер может показывать работодателям с бейджем неподтверждённого грейда; порядок карточек остаётся серверным. Подтверждённые кандидаты имеют приоритет.

После входа через FSP ID фронтенд принимает callback на `/auth/fsp-id`, сохраняет сессию через API-клиент и удаляет токены из адресной строки. Авторитетную роль получает из `auth.me()`. Новый кандидат попадает на анкету, затем отдельно сохраняет согласия. При `mode: mock` интерфейс прямо обозначает имитацию входа.

Контакты в карточке работодатель получает только от API. После отзыва доступа обновите подборку и откройте карточку заново. Фронтенд не может отозвать уже сохранённую компанией копию контактов.

## Проверки и границы

Сборка и ESLint проходят. Проверки с подменой API покрывают возврат FSP ID, регистрацию и сессию, анкету без сферы бизнеса, восстановление теста, зарплатную вилку и gross/net, принятие приглашения и отзыв доступа, сохранение потребностей, ATS и одноразовый секрет.

На текущем сервере пользователя запрос `/api/employer/needs` получил 404, а в OpenAPI обнаружился только `/api/reference` из проверки `needs|reference`. В новом `api2.js` адрес потребностей остался прежним. Эта ошибка требует проверки версии бэкенда; фронтенд сохраняет прежний адрес без догадок и обходных запросов.

Новые эндпоинты FSP ID, доступа к контактам и ATS тоже должны присутствовать в реально запущенной версии сервера. Полный прогон с этим сервером и общая Docker-сборка ещё не проверены.
