# ML в итоговой сборке

Встроенные модули находятся в `backend/app/ml/`; банк задач — в `backend/app/testing_bank/bank.py`. Отдельный FastAPI на 8001 и файлы автономного `feature/ml-core` не требуются.

Тестирование использует подготовленные тексты и серверные функции генерации данных. GigaChat во время прохождения теста не вызывается. Текущий банк: 60 размеченных Python-шаблонов для пяти направлений и четырёх грейдов. Для каждого сочетания есть easy, mid, hard. Общий алгоритмический каркас повторяется между направлениями; это ещё не полноценное покрытие профессиональных навыков каждого направления. Часть генераторов имеет фиксированные данные — их дальнейшая параметризация остаётся задачей ML-разработчика.

Резюме: pypdf извлекает текст, сервер маскирует контакты, `app/ml/resume.py` при наличии ключа вызывает GigaChat (модель по умолчанию GigaChat-Pro). При отсутствии ключа/ошибке работает встроенный парсер. Время ожидания модели ограничено. OCR сканов не интегрирован. Реальное качество разбора резюме нужно измерить на согласованной выборке.

Подбор: `app/ml/matching.py` считает локальное покрытие токенов запроса. Это не LLM-объяснение и не эмбеддинг-модель. Итоговую оценку, фильтры и понятные причины рассчитывает `matching_engine.py`. Маршрут объяснения, если оставлен в API, не является обязательным этапом выдачи.

Эталонные решения и проверки банка: `scripts/verify_hybrid_testing.py`, `tests/test_contest_generation.py`, `tests/test_all_contests.py`, `tests/test_contest_scoring.py`. Успех этих проверок не доказывает качество профессионального грейдинга, отсутствие списывания или полноту скрытых тестов.
