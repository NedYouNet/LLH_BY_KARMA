2. ЧТО ИЗМЕНЕНО ВОКРУГ ВАШЕГО БАНКА
backend/app/services/testing_engine.py выбирает ровно одну задачу каждой сложности
нужного уровня, а не 3 случайных задачи или смесь со старыми вопросами.
Вес привязан к сложности, не к случайному порядку:
easy 15 база + 5 бонус; medium 20+10; hard 35+15.
Бонус начисляется только при прохождении всех тестов. Частичное решение:
base * passed / total. Пример: hard 4/5 -> 28, hard 5/5 -> 50.
Данные создаются make(rng) при старте попытки. Онлайн-запроса LLM во время
тестирования нет. Публичный пример теперь берётся из первого теста текущего
варианта; остальные тесты и служебные ответы остаются на сервере.
Неиспользуемый ml_variants.py удалён, чтобы не смешивать альтернативные банки.

3. КОНТРАКТ ДЛЯ НОВЫХ ЗАДАЧ
Используйте текущий Template и id вида <prefix>.code.<level>_(easy|mid|hard)_<name>.
Уровень в id должен совпадать с level: Intern 0, Junior 1, Middle 2, Senior 3.
У каждой пары spec/grade должны быть все три сложности; kind=code.
make(rng) возвращает text, code.function_name, signature, examples, tests.
В tests — args и expected. Алгоритм возвращает значение Python, не читает stdin.
Контракт функции и ожидаемый тип должны совпадать с примером/скрытыми тестами.
Все направления используют Python; другие языки сейчас не поддерживаются.
Разбалловку, решение о грейде и лимит предварительных проверок не дублируйте в банке.

4. ЧЕСТНЫЕ ОГРАНИЧЕНИЯ ТЕКУЩЕГО БАНКА
Часть шаблонов параметризована, часть содержит фиксированные данные.
Поэтому нельзя писать, что каждый кандидат обязательно получает уникальный
вариант или что списывание полностью исключено. Алгоритмические каркасы между
направлениями повторяются; это не полная профессиональная оценка QA/DevOps/DS.
Следующий шаг: параметризовать фиксированные случаи, расширить граничные тесты
и добавить задачи с профильной спецификой направлений, сохранив контракт.
Не меняйте легенду так, чтобы она противоречила функции и expected.

5. РЕЗЮМЕ И ПОДБОР
GIGA_TOKEN — только переменная окружения/.env; модель задаётся GIGA_MODEL.
При отсутствии ключа работает fallback. Тесты не доказывают успешный реальный
вызов GigaChat. Перед внешним развёртыванием проверить TLS-настройки клиента.
matching.py — локальная текстовая компонента. Итог ранжирования и reasons
формирует matching_engine.py; сетевого LLM-вызова для всей выдачи нет.
Кнопка обязательного LLM-объяснения не входит в текущий сценарий интерфейса.
Не отправляйте немаскированные контакты и не меняйте профиль напрямую.
