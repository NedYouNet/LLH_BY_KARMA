# Интеграция ФСП

`backend/app/services/fsp_service.py` и связанные сервисы/маршруты отвечают за привязку ФСП, достижения, разряд и вход FSP ID. Справочные результаты читаются из `backend/data/fsp_results.xlsx`; импорт и создание шаблона — `scripts/fsp_data.py`. При отсутствии записи применяется демонстрационный реестр, если включён fallback.

В локальном Compose `FSP_ID_MODE=mock`: вход имитирует провайдера для демонстрации. Настоящая OIDC-интеграция требует issuer, client ID, секрета и регистрации приложения у провайдера. Работу с настоящим провайдером команда должна проверить отдельно; mock не является такой проверкой.

Фронтенд получает параметры через основной API `/api/auth/fsp-id/config`, показывает сведения ФСП и разряд в профиле/карточке. Секрет клиента остаётся на сервере. История ФСП — один из факторов ранжирования, а не замена результата теста.

Свежие адреса и схемы находятся в Swagger. Таблица результатов в репозитории — шаблон/демо-источник; реальные персональные записи перед публикацией должны быть отделены от публичных материалов.
