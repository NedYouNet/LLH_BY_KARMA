# Архитектура

Браузер открывает React-приложение. nginx в контейнере `frontend` пересылает `/api/` в FastAPI `backend:8000`. При разработке ту же роль выполняет прокси Vite. Авторизация, роли, попытки тестов, доступ к контактам и решение о грейде остаются в бэкенде. Данные хранятся в PostgreSQL; схему обновляет Alembic.

ML работает в том же Python-приложении: `app/ml/resume.py` разбирает текст PDF через GigaChat при наличии ключа, `app/ml/matching.py` локально вычисляет пересечение токенов. `app/testing_bank/bank.py` содержит 60 шаблонов задач. Сервер на порту 8001 не входит в эту сборку.

`testing_engine.py` генерирует и оценивает задания; `testing_service.py` хранит попытки, таймеры, проверки и историю грейда. `matching_engine.py` считает оценку соответствия; `matching_service.py` применяет её к данным базы. ФСП и ATS имеют отдельные сервисы и маршруты API.

Контейнеры: frontend (nginx), backend (Python 3.12), db (PostgreSQL 16), mailpit (тестовая почта). Публичные локальные порты: 5173, 8000, 8025. PostgreSQL доступен только внутри сети Compose.

Отдельные прототипы веток `feature/ml-core` и `Data_Scientist` не разворачиваются параллельно. Их перенос в основной API требует адаптации контрактов, а не копирования собственного `main.py` поверх приложения.
