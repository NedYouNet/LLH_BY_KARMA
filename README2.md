# Бэкенд-микросервис: Парсинг и Мэтчинг кандидатов (ФСП)



В этом репозитории реализована Data Science и базовая Backend-часть платформы для хакатона ФСП. Мы используем FastAPI для создания API, `pandas` для эффективной обработки данных, алгоритмы умного ранжирования и OCR-парсинг PDF-резюме.



## 🗂 Структура проекта



- `main.py` — Точка входа в приложение FastAPI (включает настройку CORS и подключение роутеров).

- `routers/` — Логическое разделение API:

  - `matching.py` — Эндпоинт `/api/matching/` для выдачи отранжированных кандидатов.

  - `parsing.py` — Эндпоинт `/api/parse-cv` для приема PDF и возврата JSON-профиля.

- `data_science/` — Ядро бизнес-логики:

  - `matcher.py` — Алгоритм ранжирования с весами (тесты, ФСП, скиллы, профиль).

  - `resume_parser.py` — Извлечение сущностей из PDF (PyMuPDF + Tesseract OCR).

  - `synthetic_data.py` — Скрипт генерации фейковых кандидатов для демо-базы.

  - `models.py` — Pydantic-модели (контракты данных для API).

  - `validation.py` — Скрипт для расчета метрики Precision@10.



## 🛠 Установка и локальный запуск



**Шаг 1. Системные зависимости**

Для корректной работы парсера резюме (`resume_parser.py`) в системе должен быть установлен **Tesseract OCR**.

- Windows: Скачать инсталлятор с GitHub (tesseract-ocr).

- macOS: `brew install tesseract tesseract-lang`

- Linux: `sudo apt install tesseract-ocr tesseract-ocr-rus`



**Шаг 2. Виртуальное окружение и библиотеки**

```bash

python -m venv .venv

source .venv/bin/activate  # Для Windows: .venv\Scripts\activate

pip install fastapi uvicorn pandas pydantic pymupdf pytesseract Pillow faker

```



**Шаг 3. Генерация синтетической базы**

Прежде чем запускать сервер, необходимо сгенерировать датасет кандидатов (иначе мэтчеру не с чем будет работать).

```bash

python -m data_science.synthetic_data

```

*Файл `candidates.csv` появится в папке `data_science/data/`.*



**Шаг 4. Запуск сервера**

```bash

uvicorn main:app --reload

```

API будет доступно по адресу: `http://127.0.0.1:8000`

Интерактивная документация (Swagger): `http://127.0.0.1:8000/docs`



## 📄 Механика обработки резюме (OCR и NLP)



Для минимизации ручного ввода данных реализован автоматический разбор загружаемых PDF-резюме.

* **Извлечение текста:** Используется библиотека `PyMuPDF` (`fitz`). Если PDF содержит только сканированные изображения, пайплайн автоматически переключается на оптическое распознавание символов (OCR) с помощью `Tesseract` (`pytesseract`).

* **Извлечение сущностей (RegEx):** Выделение email, номеров телефонов и стажа работы с помощью регулярных выражений.

* **Поиск навыков:** Извлечение IT-навыков путем приведения текста к нижнему регистру и поиска пересечений с предустановленным словарем.

* **Оценка полноты (Profile Completeness):** Расчет коэффициента заполненности резюме (от 0 до 1), который учитывается в итоговом ранжировании.



## 🧠 Механика подбора и логика категоризации



Алгоритм мэтчинга ищет наиболее релевантных специалистов, гарантируя анонимность до момента отклика. Процесс делится на два этапа:



### Этап 1. Жесткая фильтрация (Категоризация)

Алгоритм оставляет в выборке только тех кандидатов, чья связка специализации и грейда строго совпадает с запросом работодателя. Фильтрация по конкретным навыкам на этом этапе не производится.



### Этап 2. Взвешенное ранжирование (Scoring)

Для отфильтрованной категории вычисляется итоговый скор на основе пересечения множеств навыков (`skills_set`) и результатов первичного тестирования.



$$BaseScore = (0.40 \times TestScore) + (0.25 \times FSP) + (0.25 \times Skills) + (0.10 \times Profile)$$



Где:

* $TestScore$ — результат профессионального тестирования (от 0 до 1).

* $FSP$ — нормализованный показатель достижений ФСП.

* $Skills$ — доля совпадения навыков кандидата с требуемым стеком вакансии (пересечение множеств).

* $Profile$ — показатель заполненности профиля.



**Штраф за неподтвержденный грейд:** Если кандидат провалил тест на заявленный грейд (`is_grade_confirmed == False`), его балл принудительно умножается на штрафной коэффициент $0.5$. Он не скрывается из выдачи полностью, но падает в самый низ списка.



### Этап 3. Объяснимость выдачи (Explainable AI)

Для каждого кандидата генерируется массив `explanation`, обосновывающий его позицию в топе (совпадение по стеку, статус тестирования, достижения ФСП).



## 📊 Процедура валидации и синтетические данные



Модуль включает систему `synthetic_data.py` для генерации реалистичных профилей с помощью библиотеки `Faker`.

* **Особенности:** Распределение по грейдам, наличие FSP ID (у 50% базы), корреляция опыта с грейдом.

* **Валидация:** Скрипт `validation.py` использует метрику $Precision@10$, оценивающую долю действительно релевантных кандидатов в топ-10 выдачи.



## 🚀 Доступные эндпоинты (API)



Вся документация и форматы запросов/ответов автоматически генерируются в Swagger (`/docs`).



* **`GET /`** — Healthcheck сервера.

* **`POST /api/parse-cv`** 

  * *Назначение:* Извлечение данных из PDF.

  * *Вход:* `multipart/form-data`, файл `.pdf`.

  * *Выход:* JSON-объект `profile` с извлеченными полями (`name`, `email`, `phone`, `skills`, `experience_years`, `profile_completeness`).

* **`POST /api/matching/`**

  * *Назначение:* Получение ранжированного списка кандидатов.

  * *Вход:* JSON модели `Vacancy` (`specialization`, `grade`, `required_skills`).

  * *Выход:* Анонимный массив объектов `RankedCandidate` (без поля `name`), включающий `candidate_id`, итоговый `score`, разбивку по баллам и текстовое объяснение `explanation`.
